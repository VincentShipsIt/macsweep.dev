# IDE and editor caches

`EditorCachesView()` is an explicit, manually reviewed surface. `EditorCachesService.scan()` produces typed findings and `remove(_:)` repeats ownership and activity checks before moving selected directories to Trash. No ScanEngine or Smart Care module is registered.

JetBrains cache-directory ownership comes from installed IDE `product-info.json` records, using `dataDirectoryName` exactly. Application folders, the Toolbox installation root, running bundle paths and registered application URLs are inspected with bounded discovery. All matching installed versions are retained, including multiple installations with the same bundle identifier. Unknown products, unreadable metadata and incomplete discovery cannot establish a stale version. Recognized stale version directories under Library/Caches/JetBrains can qualify. Library/Application Support/JetBrains version directories are visible and locked because they contain configuration and plugins. Settings, keymaps, Local History and backups are never swept with a cache tree.

VS Code, Cursor and VSCodium workspaceStorage findings require one recorded local file URL in `workspace.json`. Existing workspaces, remote/ambiguous records, missing metadata, linked ancestors, protected projects, paths outside the local home and cloud-managed/offline paths are retained. Only a definite missing local path can qualify. Review explicitly warns that old workspace state will move to Trash.

Extension identities and versions come from each directory's `package.json`; the directory must agree with the manifest. Only recognized stable semantic versions are ordered numerically. The newest stable version, every prerelease/unknown version, all ties and every version referenced by `extensions.json` remain locked. A missing/unreadable registry or malformed manifest retains the entire affected extension set. Registry comparisons normalize physical paths and case conservatively, so a path alias cannot make a registered version look obsolete. No extension code or uninstall hook executes.

Electron cleanup is limited to Cache, Code Cache and GPUCache within the exact Slack, Discord, Notion and Figma Application Support directories. The owner must be identified in the installed inventory. Running apps and helpers, open files, active jobs, locks and incomplete process evidence retain the target. The UI warns that the app rebuilds these caches on next launch. Browser profiles, Local Storage and unrelated application directories are excluded.

All eligible trees are no-follow inspected with identity, parent identity, ownership, hard-link, symlink, sensitive-file and current user-rule checks. Inspection rejects settings/keymaps/history/backups and special files. Metadata reads and filesystem traversal have entry/size/time limits; partial and unavailable evidence is disclosed. Caller cancellation cancels the detached inspection and yields an incomplete result. The dedicated SafetyChecker extension authorizes only the curated owner/extension roots; generic cleanup authority remains unchanged.

The shared review lists submitted paths and estimated size. `DeletionGuard` measures the complete batch before any dispatch. Cleanup then rescans installed ownership, version/workspace/registry evidence and process activity, compares every content node, reloads protection rules and revalidates identity immediately before each removal. Per-item failures are returned while independent items continue. `CleanupFileRemover.recoverable` is the production disposal operation; a source must actually disappear with ENOENT before success is credited. Reported freed bytes remain zero; estimated bytes moved to Trash are recorded separately.

Package fixtures cover current/obsolete versions, multiple/linked IDE installations, all three editor layouts, dead/live/remote/cloud/protected workspaces, extension ordering and active registry entries, every Electron allowlist entry, running owners, incomplete evidence, locked/sensitive/linked content, replacement/content/protection changes, aggregate caps, duplicate selection, partial failures, no-op disposal and cancellation. Verification removes fixture content only, never real editor data. No administrator or unlock flow is invoked.

Primary format references: [JetBrains IDE directories](https://www.jetbrains.com/help/idea/directories-used-by-the-ide-to-store-settings-caches-plugins-and-logs.html), [VS Code extension manifests](https://code.visualstudio.com/api/references/extension-manifest), and the public AppKit `NSWorkspace.urlsForApplications(withBundleIdentifier:)` API. The app directory/bundle allowlist is cross-checked against the maintained [Homebrew cask sources](https://github.com/Homebrew/homebrew-cask/tree/master/Casks).

All new feature/test files pass strict SwiftLint. Full app-source compilation succeeded; native populated captures verified the toolbar, selectable stale IDE cache and locked installed version. Real read-only inventory returned 47 findings, zero selectable, one disclosed incomplete-inventory diagnostic in about 11 seconds. This partial inventory does not establish that the machine is clean. No real editor data was removed; no unlock or administrator flow was requested. Independent review was not requested.
