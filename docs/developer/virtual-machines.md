# VMs & Containers

`VirtualMachinesView(snapshotInventory:onReviewDocker:)` is a standalone manual inventory. It never registers VM disks with Smart Care or a cache sweep. An optional Docker callback opens the application's existing separately reviewed Docker resource workflow; raw Docker VM disks stay locked.

Every reported target is persistent state. VM disk allocation, configured guest capacity, host RAM and host swap are different quantities. The page never offers host swap-file deletion or VM stop actions. Last use remains unknown unless the manager explicitly reports a native last-use timestamp. Filesystem dates are labeled modification times, not proof of last use. Allocated scope covers only the listed paths; external or shared disks must not be inferred from a guest capacity limit. Unreadable, changing, linked or oversized trees retain an unavailable size.

## Inventory and concrete capability boundaries

| Manager | Read-only inventory | Removal capability |
| --- | --- | --- |
| OrbStack | Installed CLI `list --format json` only when local help exposes JSON; persistent `.orbstack/data` shared storage remains visible independently | Retained. Official docs expose machine deletion and reserved `docker`/`k8s` reset identities without a stopped-only refusal guarantee; shared storage is not an exclusive machine disk. |
| Colima | Native `list --json`, profile VM storage and the shared `_lima/_disks` store | Retained. Teardown can stop the VM; force bypasses the prompt and is not a verified non-stopping delete contract. Configured disk size is shown separately from measured allocation. |
| Lima | `list --json --all-fields` plus known default-home instance roots | Exact `--tty=false delete NAME`, with the restricted verified profile below. No `--force`, stop, reset or disk-unlock command. |
| UTM | Native `utmctl list` statuses plus `.utm` bundles with config.plist in known container/Documents locations | Retained. Native stopped-only deletion refusal and full external-drive ownership are unverified; the app may require automation access. |
| Parallels | Native `prlctl list -a -i --json` plus `.pvm` bundles with config.pvs in standard locations | Retained. Primary CLI documentation confirms irreversible file deletion, but does not establish an atomic stopped-only refusal contract or complete disk ownership. |
| VirtualBox | Native registered UUID list plus `showvminfo UUID --machinereadable`; standard bundles are also inventoried | Retained. Source refuses unregistering locked sessions, but `--delete` also deletes attached hard disks and differencing/saved-state data. Exclusive ownership of the complete media graph is not proven. |
| Vagrant | `box list --machine-readable` name/provider/version records and the owned boxes store | Retained. Exact provider/version removal exists, but native use checks rely on cached environment references and may request confirmation to remove an in-use box. MacSweep cannot prove complete references across all projects. No broad or forced prune. |
| Docker | CLI context identity and persistent Docker Desktop VM store | Persistent VM disk retained. Docker resources use the separate existing reviewed workflow. |
| Claude Cowork / developer environments | An installed app with bundle identifier `com.anthropic.claudefordesktop` positively establishes ownership of known `vm_bundles`, `claude-code-vm`, and `local-agent-mode-sessions` roots | Always retained as persistent environment/session state and VM downloads. Removing these may lose the environment or require downloads/setup again. They are not disposable app caches. |

Absent tools/stores are quiet. Installed tools that cannot return a complete supported inventory surface diagnostics, while independently discovered owned storage remains visible. Native identifiers and filesystem paths are distinct; missing path/size/status is never guessed. Vagrant components reject path traversal, and native identifiers are never interpreted as shell commands.

## Verified Lima operation

The enabled profile is Lima **2.2.1**, the version whose native deletion source was inspected. Other versions remain inventoried but locked. A target must be a stopped, unprotected built-in VZ instance with zero host-agent/driver PIDs, no remaining PID/socket metadata, no inspection errors or additional disks, and its exact default-home directory. All other Lima instances must also be stopped. Custom `LIMA_HOME` locations, external disks, unknown states and drivers remain retained. Agent-home symlinks or indirections cannot qualify because the default root and every descendant must pass canonical identity, current-UID ownership and SafetyChecker checks.

Primary source checks stopped/protected state before teardown. Teardown contains a process-cleanup helper, so MacSweep additionally requires zero native process IDs, no shared disks, no relevant live manager/hypervisor/open-file evidence and a complete activity snapshot. It never requests a stop or force path. All source/file/tool identity stamps, native status, protection and user rules are refreshed immediately before the exact command. Any change retains the target. The CLI binary's resolved identity and file stamp are part of the receipt evidence.

The complete reviewed selection is checked against the configured aggregate DeletionGuard cap before any dispatch, with overflow/unknown sizes rejected. Policy is refreshed during the run. Individual successful native removals require a complete fresh inventory proving the exact ID disappeared. Native failure has no filesystem fallback and produces partial receipts without dropping still-protected machines. The service reports processed target-size estimates separately from before/after available-volume observations; neither estimates nor concurrent volume changes are claimed as causally freed exclusive bytes.

## Verification

Verification (local) uses owned fixture layouts and injected native commands/activity/rules. Coverage includes all requested manager layouts, positive AI app ownership, protected state remaining visible, native parsers, unsupported/running/protected states, final-check boot/protection races, aggregate preflight with zero dispatch, changed content/identity/rules, linked contents and partial native failures. Actual discovery is read-only. No real machine, VM image, session state, swap file or process is removed or stopped during verification; no administrator/unlock prompt runs.
