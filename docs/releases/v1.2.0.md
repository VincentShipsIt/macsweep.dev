# MacSweep v1.2.0

## GUI scope

MacSweep is a native macOS 26 Tahoe app with Smart Care, Browser Cleanup,
Large & Old Files, storage review, uninstallation, maintenance, optional AI
analysis, and dedicated developer workflows. Enable **Settings → Developer →
Developer mode** to reveal Developer Disk Map, Stale Projects, Xcode Deep Clean,
Toolchains, Environment Doctor, Local Snapshots, Virtual Machines, and
IDE & Editor Caches. App Leftovers and unified Updates appear under Applications.

The Homebrew cask installs the signed, notarized app and pulls in the separate
Homebrew formula that builds and installs the CLI. The app supports signed
Sparkle updates. Full Disk Access is optional for launching;
protected sources can report partial results until permission is granted.
Deterministic scans work without AI credentials.

## Features

- Find developer storage with a bounded disk map and review stale projects.
  Separate source from generated artifacts, create verified ZIP archives, and
  review eligible clean, pushed checkouts before moving them to Trash.
- Review Xcode storage, installed toolchains, editor caches, local Time Machine
  snapshots, and virtual environments through their owning tools. Current,
  running, referenced, shared, or uncertain state stays retained. Snapshot
  thinning shows backup-history tradeoffs and requires an explicit review.
- Find app leftovers using ownership metadata. Installed or running apps,
  shared containers, and recent or uncertain data remain protected.
- Check updates across supported Homebrew, App Store, npm, pnpm, pipx, and gem
  sources. Review exact commands and see live output and individual outcomes.
  Unsupported operations remain unavailable.
- Diagnose PATH, Homebrew, launch-item, and bin-link problems with Environment
  Doctor. Only exact, freshly checked orphan files and broken links can move to
  Trash. The CLI also supports `macsweep doctor --format json`.

## Fixes

- Prevent generic cache, AI, disk-map Trash, and shred actions from bypassing
  dedicated developer-storage protections. Recheck identity, ownership,
  repository state, activity, and aggregate limits before supported cleanup.
- Preserve conversation archives, persistent VM data, current editor state,
  active Xcode resources, and referenced runtimes. VM removal is limited to an
  explicitly verified stopped Lima 2.2.1 VZ capability; other unsupported native
  operations retain their data.
- Correct scan coordination, queued cancellation, and permission retries.
  Preserve partial failures and completed action receipts, and show dated
  evidence and unknown sizes honestly.
- Keep browser service-worker cleanup within a verified isolated browser
  context; normal Brave profile data remains protected.
- Remove the deprecated Homebrew `verified` URL option and stop regenerating
  it when publishing future releases.

## Performance and cleanup limits

Heavy filesystem walks share two asynchronous admission slots. Native commands
have a separate bounded lifecycle limit, so waiting work does not starve output
readers. Cancellation reaches queued work and active process groups.

Sizes are estimates. Moving files to Trash does not free their space until Trash
is emptied. APFS allocation, shared data, and observed volume changes are not
claims of physical space recovered. Cleanup requires explicit review and fresh
safety checks; these workflows do not enable automatic destructive Smart Care
or background cleanup.

## Deferred features

The iOS companion, Mac–iOS/cloud sync, and hosted MCP adviser are deferred. The
MCP epic documents a future Vercel service with a paired local helper and local
cleanup approval; this release contains no hosted MCP implementation. Extensions
management, paid licensing, and App Store distribution are also deferred.
Optional AI analysis requires configured provider credentials. Unsupported or
uncertain cleanup capabilities remain unavailable rather than deleting data.
